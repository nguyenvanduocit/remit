## 1. What must persist for a long-lived agent, and how should it learn?

### Takeaway
The field has converged on one thesis: the model's weights are frozen, so the agent's identity and learning live in **context as state**: editable in-context memory blocks, plain files (Markdown, a filesystem, git), and reusable procedures stored as skills (SKILL.md). Platforms differ on who curates that state: the agent itself mid-task (MemGPT/Letta, Hermes, OpenClaw), background agents during idle time (Letta sleep-time, Mastra Observer/Reflector), or evolutionary search over the agent's own code (Darwin Gödel Machine).

### Cited Findings

**Letta (MemGPT lineage): "the agent is its state"**
- MemGPT ("MemGPT: Towards LLMs as Operating Systems", 12 Oct 2023, rev. 12 Feb 2024) proposes "virtual context management" modelled on OS memory hierarchies: data moves between fast and slow memory tiers so the model works beyond its fixed window, and the system "utilizes interrupts to manage control flow between itself and the user". — [arXiv 2310.08560](https://arxiv.org/abs/2310.08560) (HIGH)
- **Letta's 2026 pivot ("Our next phase", 16 Mar 2026):** "Letta builds agents that learn"; the company "made a bet at the start of this company that memory was the key to self-improving artificial intelligence" and wants agents whose lifespans outlast any single model. Memory moves from specialised database-editing tools (e.g. `core_memory_replace`) to general tools like bash over git-backed context repositories ("MemFS"); sleep-time reflection moves client-side as a subagent; skills become the main unit for packaging capability; Letta Code ("a model-agnostic agent harness with persistent memory") becomes the flagship, so users "own the memory" and "choose the model". Deprecated: tool rules ("to avoid inhibiting frontier capabilities"), templates, Letta Filesystem, server-side MCP, server-side sleep-time agents, identities. — [Letta, "Our next phase"](https://letta.com/blog/our-next-phase) (HIGH)
- Other 2026 Letta posts per the blog listing: Conversations (shared memory across concurrent experiences, 21 Jan 2026), Context Repositories (git-based memory, 12 Feb 2026), Letta Code desktop app (6 Apr 2026); a Letta Agents SDK for embedding long-running stateful agents (17 Aug 2026) is reported by one third-party page only. — [letta.com/blog](https://letta.com/blog); [API Evangelist summary](https://blogs.apievangelist.com/blogs/letta-2026-03-16-lettas-next-phase/) (MEDIUM; Agents SDK LOW)
- Letta's thesis: stateful agents learn by updating their context windows rather than model parameters; the framework persists state for long-running agents. — [Letta, "Stateful agents"](https://www.letta.com/blog/stateful-agents/) (MEDIUM, snippet)
- Memory blocks are the central structure: labelled segments of in-context memory with descriptions and character limits, edited by the agent through built-in tools when it learns something. — [Letta Core Concepts](https://docs.letta.com/core-concepts/) (MEDIUM, snippet)
- All agent data is persisted to Postgres or SQLite and exported/imported with the open **Agent File (.af)** format (launched April 2025), which captures prompts, tool definitions, execution environment, model configuration and memories, so the same agent can move between servers. — [Letta, "Agent File"](https://letta.com/blog/agent-file) (MEDIUM, snippet)
- **Sleep-time compute** (April 2025): enabling it creates a second "sleep-time agent" alongside the main agent that edits shared memory during idle periods, so the primary agent need not. — [Letta blog via search](https://letta.com/blog/agent-file); paper [arXiv 2504.13171](https://arxiv.org/abs/2504.13171), 17 Apr 2025 (HIGH for the paper, MEDIUM for SDK behaviour)
- **Letta Code** (launched Dec 2025): a "stateful agent harness for creating agents that are more like people than tools", with system-prompt learning and skill learning, a `/sleeptime` command for periodic "dreaming", and memory blocks tracked in git ("Context Repositories"). — [Letta Code README](https://cdn.jsdelivr.net/gh/letta-ai/letta-code@main/README.md); [Letta, "Letta Code"](https://www.letta.com/blog/letta-code) (MEDIUM, snippet)

**Hermes Agent (Nous Research): "the only agent with a built-in learning loop"**
- Self-described as a self-improving autonomous agent, "not a coding copilot or a chatbot wrapper", designed to run continuously on infrastructure you choose. — [Hermes Agent docs](https://hermes-agent.nousresearch.com/docs), 2026 (HIGH)
- Three memory layers: agent-curated memory with periodic nudges to save knowledge; FTS5 search over past sessions with LLM summarization; Honcho-based "dialectic user modeling" that builds "a deepening model of who you are across sessions". — [Hermes Agent docs](https://hermes-agent.nousresearch.com/docs) (HIGH)
- Skills: the agent creates skills from past work, refines them during use, and reuses them as procedural memory; skills follow the open agentskills.io standard and are shared through a Skills Hub. — [Hermes Agent docs](https://hermes-agent.nousresearch.com/docs) (HIGH)
- Memory lives in Markdown files (memory.md, user.md) and each memory entry is security-scanned before being written to disk; released 25 Feb 2026 under MIT. — [Better Stack guide](https://betterstack.com/community/guides/ai/hermes-agent/); [jimmysong.io](https://jimmysong.io/ai/hermes-agent) (LOW, secondary)

**OpenClaw (open-source always-on personal agent)**
- Official framing: "an open-source AI assistant that runs on your own hardware and meets you in every chat app you already use"; a self-hosted Gateway is "the single source of truth for sessions, routing, and channel connections"; skills "teach the agent repeatable procedures it loads on demand"; scheduled work via "cron jobs, hooks, and webhooks"; maintained by the OpenClaw Foundation, "an independent 501(c)(3)" ("no lab owns it"). The docs home page carries no dates and does not describe memory internals or the heartbeat. — [OpenClaw docs](https://docs.openclaw.ai) (HIGH)
- Memory is plain Markdown (MEMORY.md for curated long-term facts, a memory/ directory for logs), persistent across restarts, local and human-readable; skills are Markdown with YAML frontmatter distributed via the ClawHub registry, which has been targeted by malicious skills. — [clawdocs core concepts](https://clawdocs.org/getting-started/core-concepts); [OpenClaw Unpacked](https://aiagentssimplified.substack.com/p/openclaw-unpacked) (LOW, community docs; official docs at docs.openclaw.ai not fetched)

**Manus: the filesystem is the memory**
- "The file system as the ultimate context in Manus: unlimited in size, persistent by nature, and directly operable by the agent itself." Compression must be restorable (drop a page's content, keep its URL or sandbox path). Context is kept append-only and deterministically serialized because KV-cache hit rate is "the single most important metric for a production-stage AI agent" (cached Sonnet input 0.30 vs 3 USD/MTok). — [Manus, "Context Engineering for AI Agents"](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus), Yichao Ji, 18 Jul 2025 (MEDIUM, snippet of the primary post)
- Tool availability is controlled by logit masking rather than removing tools mid-task, to keep the prefix stable. — same source (MEDIUM)
- Manus is now part of Meta (banner on the same post). — [manus.im](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus?hl=en-GB) (MEDIUM; acquisition date not confirmed in this session)

**Mastra: memory by background observation**
- Observational Memory (shipped in Mastra 1.0): an Observer agent compresses conversations into dense, timestamped observations, and a Reflector agent periodically reorganizes long-term memory; the full prompt cache is invalidated only on reflection. — [Mastra research: Observational Memory](https://mastra.ai/research/observational-memory); [Mastra blog](https://mastra.ai/blog/observational-memory) (MEDIUM, snippet)

**Skills as learned procedures (Anthropic Agent Skills / Claude Code)**
- A skill is a folder with SKILL.md (YAML name + description, markdown instructions); progressive disclosure means only name and description sit in context at startup and the body loads when a task needs it. Shipped 16 Oct 2025, opened as a standard at agentskills.io on 18 Dec 2025. — [Anthropic, "Equipping agents for the real world with Agent Skills"](https://www.anthropic.com/research/equipping-agents-for-the-real-world-with-agent-skills); [VentureBeat](https://venturebeat.com/ai/anthropic-launches-enterprise-agent-skills-and-opens-the-standard) (MEDIUM)
- Adopted by roughly 26-40 clients (GitHub Copilot, VS Code, Cursor, OpenAI Codex, Gemini CLI); counts vary by source. — [Unite.AI](https://www.unite.ai/anthropic-opens-agent-skills-standard-continuing-its-pattern-of-building-industry-infrastructure) (LOW)
- Hermes (above) and OpenClaw both store learned skills in this same format, making SKILL.md the de facto unit of procedural memory across always-on agents. — [Hermes docs](https://hermes-agent.nousresearch.com/docs) (HIGH for Hermes)

**Workflow/skill induction research**
- Agent Workflow Memory (Wang, Mao, Fried, Neubig; arXiv Sep 2024, ICML 2025): induces reusable workflows from past trajectories (offline or online) and adds them as text to the prompt. — [PMLR v267](https://proceedings.mlr.press/v267/wang25bx.html); [arXiv 2409.07429](https://arxiv.org/abs/2409.07429) (MEDIUM)
- Voyager (25 May 2023): an LLM agent in Minecraft with an automatic curriculum, an ever-growing executable skill library (code), and iterative self-verification. — [arXiv 2305.16291](https://arxiv.org/abs/2305.16291) (HIGH for date and title; mechanism MEDIUM, from training knowledge of the abstract)

**Self-modifying agents**
- Darwin Gödel Machine (Sakana AI + UBC, May 2025): keeps an archive of coding agents; each generation an agent rewrites its own code, and the change is kept only if it scores better on a benchmark (empirical validation replaces Gödel-machine proofs). — [Sakana AI, DGM](https://sakana.ai/dgm/); [arXiv 2505.22954](https://arxiv.org/abs/2505.22954) (MEDIUM)

**Learning by training, not by memory (Kimi)**
- Kimi K2.5 Agent Swarm (Jan 2026): a trainable orchestrator learns (via PARL reinforcement learning) to spawn up to 100 frozen sub-agents over up to 1,500 steps with no predefined roles; only the orchestrator is updated. K2.6 (20 Apr 2026) raised the limit to 300 sub-agents. — [Kimi K2.5 blog](https://www.kimi.com/blog/kimi-k2-5); [arXiv 2602.02276](https://arxiv.org/pdf/2602.02276); [Kimi help: Agent Swarm](https://www.kimi.ai/help/agent/agent-swarm) (MEDIUM)

**Big-lab hosted memory (Google, OpenAI)**
- Google Vertex AI / Agent Platform Memory Bank (public preview 8 Jul 2025): uses generative models to "generate memories" from sessions to "personalize agent interactions"; Sessions hold short-term context and Memory Bank long-term "user preferences and facts"; memory revisions are inspectable; IAM Conditions, CMEK, VPC-SC and data residency are supported. — [Google Cloud docs](https://docs.cloud.google.com/agent-builder/agent-engine/memory-bank/overview) (HIGH); preview date from [Virtualization Review](https://virtualizationreview.com/articles/2025/07/09/googles-vertex-ai-memory-bank-and-the-industry-shift-to-persistent-context) (MEDIUM)
- OpenAI ChatGPT memory has two controls: "Reference saved memories" (details the user asked it to remember) and "Reference chat history" (information drawn from past chats, which changes as ChatGPT updates what is most useful to remember); temporary chats neither use nor create memories; deleting a chat does not delete a memory made from it. — [OpenAI Help: Memory FAQ](https://help.openai.com/en/articles/8590148); [OpenAI Help: reference saved memories](https://help.openai.com/en/articles/11146739); [OpenAI, "Memory and new controls for ChatGPT"](https://openai.com/index/memory-and-new-controls-for-chatgpt/) (MEDIUM, help-center snippets; article dates not shown)
- OpenAI, "Dreaming: Better memory for a more helpful ChatGPT" (4 Jun 2026): dreaming is a background process that learns across many conversations and synthesizes the memory state so context stays fresh; a first version shipped with the April 2025 memory update, the timeline runs from "Dreaming V0" (2025) to "Dreaming V3" (2026), it is now the shared memory foundation for all users, and serving it to Free users reportedly costs ~5x less compute. — [OpenAI post](https://openai.com/index/chatgpt-memory-dreaming/) (MEDIUM: located on openai.com, but the page returned HTTP 403 to fetch, so content is from search snippets and forum quotes); rollout to US Plus/Pro on 4 Jun 2026 — [letsdatascience](https://letsdatascience.com/news/openai-upgrades-chatgpt-memory-architecture-for-fresher-pers-b26b51d5) (LOW)
- Recall figures conflict: one outlet reports factual recall 67.9% → 82.8% ([techlusive](https://www.techlusive.in/news/chatgpt-memory-upgrade-dreaming-system-openai-1665110/amp/)), another 41.5% → 82.8% ([tech-insider](https://tech-insider.org/chatgpt-vs-claude-vs-gemini-memory-2026/)); neither verified against OpenAI's page (LOW).
- Users object that dreaming revises or drops memories it judges stale without notice and offers no way to pin a memory. — [OpenAI community forum](https://community.openai.com/t/dreaming-v3-sacrifices-real-personalization-for-compute-savings-a-power-user-s-perspective/1383010) (MEDIUM, user opinion)

**Genspark: no long-lived self, a mixture of agents**
- "Less control, more tools": the model plans its own steps over hardwired flows; launch-era engine combined nine LLMs, 80+ tools and 10+ datasets, with models cross-checking each other. — [Genspark/MainFunc, "Less control, more tools"](https://mainfunc.ai/blog/genspark_less_control_more_tools); [Anthropic customer story](https://www.anthropic.com/customers/genspark) (MEDIUM). Later "30+ models" claims are unverified (LOW).

### Inferences
- Three persistence layers recur everywhere: **identity/profile** (Letta persona block, Hermes user.md + Honcho, OpenClaw MEMORY.md), **episodic recall** (session search, Mastra observations, Letta archival memory), and **procedures** (skills). Remit's employee memory plus skill library maps onto the same three. (MEDIUM, inference)
- The leading products store memory as text the owner can read and version (Markdown, git). This makes memory inspectable and portable (.af, agentskills.io) and is a deliberate bet against opaque vector stores. (MEDIUM)
- Letta's own 2026 pivot is the strongest signal of convergence: the originator of agent-managed memory tools replaced them with bash over git-backed files, client-side sleep-time subagents and skills, the same shape Hermes, OpenClaw and Claude Code use. (MEDIUM-HIGH, from [Letta, Mar 2026](https://letta.com/blog/our-next-phase))
- Two learning loci compete: in-context/file learning that any model can use (Letta, Hermes, Mastra, Skills) and weight-level learning owned by model labs (Kimi PARL). Only the first is available to a platform that does not train models. (MEDIUM)
- Background curation (sleep-time agent, Observer/Reflector) is becoming the default over in-turn memory edits, because it keeps the foreground turn fast and its prompt cache stable. (MEDIUM)

### Gaps
- OpenClaw's memory internals and heartbeat are not on the official docs home page; they rest on community docs (LOW). Deeper official pages not read.
- OpenAI's Dreaming post blocks automated fetching (HTTP 403); its exact recall figures and how they were measured stay unverified until someone reads it in a browser.
- No source found describing how Hermes decides a skill is wrong and retires it.

## 2. How do they make work survive crashes, waits for humans or events, and days of runtime?

### Takeaway
Two camps. **Durable-execution engines** (Temporal, Restate, Inngest, Trigger.dev, DBOS) record every model call and tool call in an event history or journal, replay it after a crash, and suspend with no running process while waiting days for a signal or a human. **Agent frameworks** (LangGraph, Letta) persist *state* (checkpoints, memory in a database) but a single run still lives in one process. The two are now being composed (Temporal plugins for LangGraph, OpenAI Agents SDK, Vercel AI SDK).

### Cited Findings
- Temporal Agent Harness (early look, 20 Aug 2026, pre-public-preview): every agent runs as a Temporal Workflow; it "can survive worker crashes and deployments, wait minutes or days for something to happen", retries model/tool calls by policy, and resumes without rerunning completed work from event-sourced history. — [Temporal blog](https://temporal.io/blog/temporal-agent-harness-durable-agent-infrastructure) (HIGH)
- The harness wraps an existing inner SDK (Gemini, OpenAI Agents SDK, PydanticAI); a "turn" invokes the inner harness exactly once; tool calls pass a policy layer because "there should be a seam between the model deciding to use a capability and that capability actually executing"; approvals "pause execution ... and resume durably when the decision arrives"; all activity is emitted as structured AgentEvents for UIs, audits and replay. — [Temporal blog](https://temporal.io/blog/temporal-agent-harness-durable-agent-infrastructure) (HIGH)
- Temporal's OpenAI Agents SDK integration went GA on 23 Mar 2026; a Vercel AI SDK plugin (Jan 2026) leaves existing code largely unchanged. — [Temporal blog, Vercel AI SDK](https://temporal.io/blog/building-durable-agents-with-temporal-and-ai-sdk-by-vercel); GA date from [dev.to guide](https://dev.to/jangwook_kim_e31e7291ad98/temporal-for-ai-agents-durable-execution-guide-2026-9hf) (MEDIUM / LOW for the GA date)
- Temporal raised a $300M Series D at a $5B valuation in Feb 2026; OpenAI, Replit and Lovable named as users. — [dev.to guide](https://dev.to/jangwook_kim_e31e7291ad98/temporal-for-ai-agents-durable-execution-guide-2026-9hf); [ZenML case study](https://www.zenml.io/llmops-database/building-reliable-production-ai-agents-with-durable-execution-infrastructure) (LOW, not checked against a primary announcement)
- Temporal argues LangGraph "checkpoints state, but checkpoints are not durable execution": a LangGraph run lives in one process and dies with it; its LangGraph plugin adds durable execution and supports interrupts. — [Temporal, LangGraph plugin](https://temporal.io/blog/temporal-langgraph-plugin-durable-execution) (MEDIUM, vendor framing)
- LangGraph persistence: checkpointers store thread-scoped state for conversation continuity, human-in-the-loop, time travel and fault tolerance; in-memory checkpoints are lost on restart; production uses PostgresSaver; long-term memory goes in Stores (cross-thread). — [LangGraph persistence docs](https://docs.langchain.com/oss/python/langgraph/durable-execution) (HIGH)
- On resume after an `interrupt`, the interrupted node re-runs from its start, so side effects before the interrupt must be idempotent. — [developersdigest comparison, 2026](https://www.developersdigest.tech/blog/durable-ai-agent-frameworks-compared-2026) (MEDIUM; matches LangGraph's documented interrupt semantics)
- Inngest: the agent runs until it needs input, calls `step.waitForEvent()` with a match condition and suspends; "nothing stays running during the wait"; the matching event (human approval, webhook, another agent's message) resumes it. AgentKit tools wait for humans the same way once the network is wrapped in an Inngest function. — [Inngest, Durable Agents](https://www.inngest.com/docs/learn/durable-agents); [AgentKit HITL](https://agentkit.inngest.com/advanced-patterns/human-in-the-loop) (MEDIUM). A 7-day maximum wait is claimed by a third party only (LOW).
- Restate positions itself as durable service code: journaled calls, state, retries on transient errors such as rate limits, and very large numbers of concurrent agent runs on FaaS or containers. — [Restate docs: AI agents](https://docs.restate.dev/use-cases/ai-agents) (MEDIUM)
- Trigger.dev's agent guide: "a durable session per conversation, with streaming and resumability handled for you" (`chat.agent()`). — [Trigger.dev AI agents overview](https://trigger.dev/docs/guides/ai-agents/overview) (HIGH)
- Trigger.dev waitpoint tokens: `wait.createToken()` then `wait.forToken(id)` pauses the run, "commonly used for approval workflows"; "If omitted, the token has no timeout" (examples up to `"4w"`); a token is completed by `wait.completeToken()` from anywhere, a POST to the token's URL, the REST API, or from a browser with a scoped public access token. The page does not say whether a waiting run is checkpointed or uses compute. — [Trigger.dev wait-for-token docs](https://trigger.dev/docs/wait-for-token) (HIGH); "sleeps without consuming resources" only from a docs snippet (MEDIUM)
- Hatchet: "built around the concept of durability"; "Every task and agent invocation is durably persisted in Hatchet, allowing for debugging, retries and replays"; agents can "automatically checkpoint their current state and pick up where they left off when faced with unexpected errors". — [Hatchet docs](https://docs.hatchet.run/home) (HIGH; page undated)
- Hatchet durable tasks "only do one of two things": wait (durable sleep or an event, combinable with OR so whichever comes first wins) or spawn child tasks; "every time a piece of a durable task completes, it creates a new checkpoint" in a durable event log, so after a crash the task replays from the last checkpoint "without needing to e.g. replay the human-in-the-loop portions of the task, such as approvals". — [Hatchet durable execution docs](https://docs.hatchet.run/home/durable-execution) (HIGH; undated)
- DBOS (24 Feb 2025): "durable execution as an open source library" built on Postgres, with no separate orchestration server; an interrupted step should "automatically recover upon restart"; a human approval is a child workflow that emails a manager and blocks on `DBOS.recv` with a timeout until an endpoint calls `DBOS.send`. Integrations wrap OpenAI Agents SDK and Pydantic AI agents as durable workflows with each tool call a step. — [DBOS blog](https://dbos.dev/blog/durable-execution-crashproof-ai-agents) (HIGH); [DBOS + Databricks](https://www.dbos.dev/blog/building-durable-agents-dbos-databricks) (MEDIUM)
- Trigger.dev is described as a TypeScript-first durable platform for agents and long-running jobs (queues, retries, scheduling, observability); comparisons judge durability guarantees across Inngest/Trigger.dev/Temporal as similar, with language fit and DX deciding. — [youngju.dev comparison, May 2026](https://www.youngju.dev/blog/culture/2026-05-14-durable-execution-engines-2026-temporal-restate-inngest-trigger-dev-dbos-deep-dive-2026.en); [ZenML](https://www.zenml.io/blog/inngest-alternatives) (LOW, third-party)
- Hermes' answer to long runtime is cheap hosting, not replay: six terminal backends; on Daytona/Modal "your environment hibernates when idle, costing nearly nothing"; the agent is "not tied to your laptop". — [Hermes docs](https://hermes-agent.nousresearch.com/docs) (HIGH)
- OpenClaw's heartbeat only works while the instance stays running. — [clawdocs](https://clawdocs.org/getting-started/core-concepts) (LOW)

### Inferences
- "Durable" means two different things: durable *state* (memory, checkpoints; Letta, LangGraph, Hermes, OpenClaw) and durable *execution* (exactly-once-ish replay of an in-flight run; Temporal, Restate, Inngest). Personal always-on agents mostly have only the first and lose in-flight work on crash. (MEDIUM)
- The Temporal Agent Harness design (turn as unit, policy seam before tool execution, typed event stream) is the closest public analogue to Remit's chain/turn/rail model. (MEDIUM)
- Every engine forces idempotency onto side-effecting steps; LangGraph's re-run-the-node semantics make this explicit. (HIGH, follows from cited docs)

### Gaps
- Trigger.dev documents no maximum waitpoint timeout and does not state on the wait-for-token page how a waiting run is checkpointed.
- Hatchet's durable-execution page states no limits (timeouts, log size).
- No public failure-rate or incident data for any platform's agents in production.

## 3. What is ambient / event-triggered agency, and how is the human notified and asked?

### Takeaway
"Ambient agents" (Harrison Chase, Jan 2025) listen to an event stream or a schedule instead of a chat box, act in the background, and pull the human in through three patterns: **notify**, **question**, **review**. Personal agents implement the same idea with heartbeats and cron, delivering through chat apps the owner already uses; durable engines implement "ask" as a durable wait on an event.

### Cited Findings
- Chase: ambient agents listen to an event stream and act on it, possibly on several events at once, and should not be fully autonomous; the human is involved through notify, question and review; many run on a schedule, supported by LangGraph Platform cron jobs. — [LangChain, "Introducing ambient agents"](https://www.langchain.com/blog/introducing-ambient-agents), Jan 2025 (MEDIUM, snippet)
- OpenClaw heartbeat: a periodic poll that lets the agent check things unprompted; HEARTBEAT.md holds the checklist (email, calendar, memory sync) run at configurable intervals. — [clawdocs](https://clawdocs.org/getting-started/core-concepts); [OpenClaw architecture, The Agent Stack](https://theagentstack.substack.com/p/openclaw-architecture-part-1-control) (LOW)
- Hermes: built-in cron jobs "can deliver results to any supported platform", and one messaging gateway connects 20+ platforms (CLI, Telegram, Discord, Slack, WhatsApp, Signal, Email, SMS); the docs state these as two features and do not show a cron result arriving on a given platform. The docs do not explain the notification/ask protocol beyond delivery. — [Hermes docs](https://hermes-agent.nousresearch.com/docs) (HIGH)
- Temporal harness: approvals, callbacks, timers and other external events start a new turn; approval policies pause and resume durably, even days later. — [Temporal blog](https://temporal.io/blog/temporal-agent-harness-durable-agent-infrastructure) (HIGH)
- Inngest: a Slack or dashboard click sends an event that resolves `waitForEvent`; resume or abort on the answer. — [Inngest HITL docs](https://www.inngest.com/docs/ai-patterns/human-in-the-loop) (MEDIUM)

### Inferences
- Every platform found here still routes "ask" to the human; none delegates the decision to another agent by default. Remit's rule that no agent waits on the owner and the Assistant decides items for him ([AGENTS.md:63](../../../AGENTS.md); `docs/adr/0087-no-agent-waits-on-the-owner-and-a-release-seat-puts-remit-live.md`) goes further than any public platform found. (Remit rule: HIGH, read in the repo; "further than any platform": MEDIUM, bounded by this session's search coverage)
- Event trigger, durable wait and notification channel are separable pieces: Chase's patterns name the human-facing contract; Temporal/Inngest provide the wait; Hermes/OpenClaw provide the channel. (MEDIUM)

### Gaps
- No primary source on how OpenClaw or Hermes throttle notifications or batch questions to avoid flooding the owner.
- No data on how often ambient agents' questions are answered or ignored.

## 4. What evidence exists that memory and self-improvement actually help?

### Takeaway
Evidence is real but narrow and mostly self-reported. Strongest: workflow induction (AWM, peer-reviewed), DGM's archive-based self-modification (20%→50% SWE-bench), and sleep-time compute (~5x less test-time compute). The most important negative result: **self-generated skills gave no average benefit** while curated skills gave about +16 points (SkillsBench, 2026). Memory benchmarks (LoCoMo, LongMemEval) are vendor-run and contested; a plain filesystem agent rivals specialised memory layers.

### Cited Findings
- **SkillsBench** (arXiv 2602.12670, Feb 2026; NeurIPS 2026 poster): curated skills raised average pass rate by 16.2 pp (poster: 16.4 pp), ranging from ~+4.5 in software engineering to ~+51.9 in healthcare; 16-18 of 84 tasks got worse; **self-generated skills averaged no benefit (poster: -1.3 pp)**, read as models being unable to reliably author the procedural knowledge they benefit from; focused skills with 2-3 modules beat comprehensive documentation. — [arXiv abs](https://arxiv.org/abs/2602.12670); [NeurIPS 2026 poster](https://neurips.cc/virtual/2026/poster/139353); [papers.cool](https://papers.cool/arxiv/2602.12670) (MEDIUM; v1 and poster numbers differ)
- **Agent Workflow Memory**: +24.6% relative step-wise success on Mind2Web (cross-task) and +51.1% relative success on WebArena, with fewer steps; online AWM's margin over baselines grows from 8.9 to 14.0 absolute points as train-test distribution gaps widen. — [PMLR v267 / ICML 2025](https://proceedings.mlr.press/v267/wang25bx.html) (MEDIUM)
- **Darwin Gödel Machine**: SWE-bench 20.0%→50.0%, Polyglot 14.2%→30.7%; without self-improvement it plateaus at 39.0%, without open-ended archive exploration 23.0%; best DGM agents still trailed top human-designed agents (~70% per IEEE Spectrum at the time). — [arXiv 2505.22954](https://arxiv.org/abs/2505.22954); [Sakana](https://sakana.ai/dgm/); [IEEE Spectrum](https://spectrum.ieee.org/evolutionary-ai) (MEDIUM)
- **Sleep-time compute** (Letta/UC Berkeley authors incl. Packer, Wooders, Stoica, Gonzalez; 17 Apr 2025): "~5x" less test-time compute for the same accuracy on Stateful GSM-Symbolic and Stateful AIME; scaling sleep-time compute raises accuracy "by up to 13%" and "18%" respectively; average cost per query falls "by 2.5x" when amortised across related queries. — [arXiv 2504.13171](https://arxiv.org/abs/2504.13171) (HIGH)
- **Letta filesystem experiment** (12 Aug 2025): putting LoCoMo history in files with grep/search/open/close tools and GPT-4o mini scored 74.0%, above Mem0's then-reported 68.5% for its graph variant; Letta's explanation is that models are heavily post-trained on filesystem operations for coding. — [Letta, "Benchmarking AI Agent Memory: Is a Filesystem All You Need?"](https://www.letta.com/blog/benchmarking-ai-agent-memory) (MEDIUM). Mem0 now advertises 92.5 vs Letta's 74.0 on its own comparison page — [Mem0 vs Letta](https://mem0.ai/compare/mem0-vs-letta) (LOW, vendor). A third-party audit reports methodological problems in LoCoMo itself — [DEV Community](https://dev.to/varun_pratapbhardwaj_b13/5-ai-agent-memory-systems-compared-mem0-zep-letta-supermemory-superlocalmemory-2026-benchmark-59p3) (LOW).
- **Mastra Observational Memory** on LongMemEval_s (500 questions, ~57M tokens): 84.23% with GPT-4o vs 80.05% for Mastra's own RAG; 94.87% with gpt-5-mini; ~30k-token average context; memory ingested before the eval. Claude 4.5 models reportedly did not work as Observer/Reflector at the time. — [Mastra research](https://mastra.ai/research/observational-memory); [VentureBeat](https://venturebeat.com/data/observational-memory-cuts-ai-agent-costs-10x-and-outscores-rag-on-long) (MEDIUM, vendor-run, no independent replication found)
- **Voyager**: "obtains 3.3x more unique items, travels 2.3x longer distances, and unlocks key tech tree milestones up to 15.3x faster than prior SOTA". — [arXiv 2305.16291](https://arxiv.org/abs/2305.16291) (HIGH); transfer of the skill library to new worlds is from training knowledge (MEDIUM)
- **Kimi Agent Swarm**: up to 4.5x lower latency than single-agent baselines; Moonshot internal evals report 80% lower end-to-end runtime; gains are measured on highly parallel tasks and shrink with sequential dependencies. — [arXiv 2602.02276](https://arxiv.org/pdf/2602.02276); [morphllm analysis](https://www.morphllm.com/kimi-k2-5-agent-swarm) (MEDIUM / LOW for the caveat)
- **Genspark** reported 87.8% on GAIA (company claim relayed by secondary source). — [eesel.ai](https://www.eesel.ai/blog/genspark-ai) (LOW)
- **Hermes**: a "~40% reduction in research task time" community benchmark is cited without a primary source. — [Better Stack](https://betterstack.com/community/guides/ai/hermes-agent/) (LOW)
- Letta claims Letta Code is the #1 model-agnostic open-source harness on TerminalBench (Dec 2025). — [Letta Code blog](https://www.letta.com/blog/letta-code) (LOW, vendor)

### Inferences
- Memory and learned procedures help most when **curated or verified**: AWM induces from successful trajectories, DGM keeps a change only if it scores higher, SkillsBench's curated skills help while unchecked self-written skills do not. Self-improvement without a judge is not supported by the evidence found. (MEDIUM-HIGH, consistent across three independent sources)
- Specialised memory stores have not clearly beaten "files + grep + a capable model"; the gap is within benchmark-methodology noise. (MEDIUM)
- Background/idle-time processing (sleep-time compute, Mastra Reflector) has the cleanest cost evidence, but on synthetic "stateful" variants of maths benchmarks, not on real long-lived work. (MEDIUM)
- No study found measures an agent improving over weeks of real deployment; all evidence is benchmark-episodic. (MEDIUM, bounded by search coverage)

### Gaps
- No independent replication of Mastra, Mem0 or Letta memory scores found.
- No public evaluation of Hermes', OpenClaw's or Letta Code's self-learned skills over time.
- No evidence found on memory *harm* (stale or poisoned memories degrading behaviour) beyond OpenClaw's malicious-skill reports.
