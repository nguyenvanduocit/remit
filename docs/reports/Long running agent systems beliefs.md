# Peers keep the human gate Remit removed

The long-running agent field has converged on a shared engineering core: state lives outside the context window, one writer works per isolated workspace, a separate and skeptical evaluator checks the work, deterministic code forms the spine, and the LLM's autonomy is bounded inside it. Remit already holds almost all of that core and goes beyond it in four places: judges that rule for the customer, a `not_met · untried` check on unproven "could not" claims, memory admitted only through a verdict, and a headline KPI measured in owner hours. The disagreement is about **who decides when the human is absent**. No product or lab studied lets an agent hold the owner's approval authority. Paperclip's design states it outright: expiry closes a request and never approves one. Linear moved accountability back to a named human. Anthropic's own experiment found that a same-model "CEO" agent made the shop worse. Remit's newest rule, "no agent waits on the owner" (ADR-0087), makes the Assistant that decider for every non-secret item, including irreversible ones. That rule is Remit's boldest bet and its least supported one. Three other beliefs are at risk on the same evidence: a judge is a weaker model of the same family as the author it grades, memory has no proof it helps over weeks of work, and the stall rail can see idleness but not busy loops that make no progress. On the other side, the evidence supports Remit's bet on next year's models: METR's measured horizons double about every four months, and the labs are removing scaffolding as fast as the models allow. Every recommendation below carries a confidence label, and the ones that touch ADR-0087 are the owner's call, because they conflict with his stated intent.

*Coverage: four research notes, about 220 tool calls by their authors, read in full. Of Remit's documents, `AGENTS.md` sections "Where we are" and "Agent-centric", `docs/remit-design.md` in full, and `docs/design.md` sections Intent, Model, How results are checked, Objectives, Employees, Memory, Outcomes, The Assistant and The provider (about 600 of 1,778 lines), plus ADR-0063, ADR-0087 and `crates/orch/src/schedule.rs:207-460`. Reddit could not be reached, so first-hand community critique comes from GitHub issues and blogs. UI and UX findings are in `docs/research-peers-product/report.md` and are not repeated here.*

## Every survivor runs bounded autonomy on a deterministic spine

The projects that are still alive in November 2026 agree on more than their marketing suggests. **The work's continuity lives outside the model.** Anthropic's long-running harness has an initializer agent write a feature list with every item "marked as 'failing'", plus a progress file and a git commit that each later session reads first ([Anthropic](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)). OpenAI calls "durable project memory" "the most important technique" ([OpenAI](https://developers.openai.com/blog/run-long-horizon-tasks-with-codex)). Paperclip sells itself on the fix for "on reboot you lose everything", using a DB-backed wakeup queue ([Paperclip README](https://github.com/paperclipai/paperclip/blob/master/README.md)). Temporal's agent harness makes each agent a workflow that "can survive worker crashes and deployments, wait minutes or days", and places "a seam between the model deciding to use a capability and that capability actually executing" ([Temporal](https://temporal.io/blog/temporal-agent-harness-durable-agent-infrastructure)). That seam is Remit's gate, and the turn as the unit of work is Remit's card turn.

**Writes stay single-threaded.** Cognition argued against multi-agent systems in 2025 and reversed ten months later, but kept the core rule: "writes stay single-threaded and the additional agents contribute intelligence rather than actions" ([Cognition](https://cognition.com/blog/multi-agents-working)). Conductor reduces parallel work to one decision, whether agents share a workspace or move independently ([Conductor](https://www.conductor.build/docs/core/parallel-agents)). Anthropic's research system gained **90.2%** with parallel subagents, but on breadth-first, read-only research, at about 15 times the tokens, and Anthropic itself says shared-context work like coding is a poor fit ([Anthropic](https://www.anthropic.com/engineering/multi-agent-research-system)). Remit's one agent per repository worktree (`docs/design.md:31-33`) and its sequential hand-over follow this consensus.

**The doer does not grade itself.** Agents "reliably skew positive when grading their own work", and tuning a separate evaluator to be skeptical is "far more tractable" than self-criticism ([Anthropic harness design](https://www.anthropic.com/engineering/harness-design-long-running-apps)). Devin Review runs against Devin before a human looks, and a "clean context leads to a notable improvement" ([Cognition](https://cognition.com/blog/multi-agents-working)). Jules puts a Planning Critic in front of every plan that runs without human sign-off ([Jules changelog](https://jules.google/docs/changelog/2026-01-26-1)).

**The spine is deterministic and the model works inside it.** CrewAI's founder: "The Flow enforces business logic that can't be negotiated, the agents don't decide whether to do these steps" ([CrewAI](https://blog.crewai.com/agentic-systems-with-crewai/)). OpenAI's harness team enforces "invariants, not micromanaging implementations" through custom lints whose messages carry fix instructions to the agent ([OpenAI](https://openai.com/index/harness-engineering/)). Project Vend learned that "bureaucracy matters": forced lookups before quoting removed most negative-margin weeks ([Anthropic, Vend 2](https://www.anthropic.com/research/project-vend-2)). The **skill file** (SKILL.md) has become the shared unit of procedural memory across Claude Code, Hermes, OpenClaw and Letta ([Hermes docs](https://hermes-agent.nousresearch.com/docs); [Letta](https://letta.com/blog/our-next-phase)).

Remit holds every one of these, mostly as code: one writer per chain, `act` runs once per request id, every turn's events are recorded in SQLite, approvals are tied to a patch id, and checks are declared by the repository and run in a jail (`docs/remit-design.md:78-84`, `docs/design.md:587-600`). None of this needs to change.

## The field splits on hierarchy, the human gate, and who curates memory

**Hierarchy.** Paperclip is the only large project that still models a company: a CEO at the root, an org chart, per-agent "token salary" budgets and a human "board" ([Paperclip PRODUCT.md](https://github.com/paperclipai/paperclip/blob/master/doc/PRODUCT.md)). Multica rejects it in so many words: "not an autonomous company running beyond human control" ([Multica VISION](https://github.com/multica-ai/multica/blob/main/VISION.md)). The evidence sides with Multica. Vend's CEO agent "shared many of the deficiencies and blind spots" of the agent it managed, authorized lenient requests about eight times as often as it denied them, and profit came "in spite of the CEO". A narrowly scoped agent with a separate role (Clothius) worked better ([Anthropic, Vend 2](https://www.anthropic.com/research/project-vend-2); [The Decoder](https://the-decoder.com/anthropics-ai-store-makes-money-while-debating-eternal-transcendence/)). A Multica user who left Paperclip called it "too chatty, spending millions of tokens just negotiating and delegating between themselves" ([multica#815](https://github.com/multica-ai/multica/issues/815)). The same thread shows what users do want: **introspectable, typed structure**. Instructions written as free text are "brittle, opaque, and not introspectable. Neither agent can answer 'who are my reports?'" Remit's typed reporting line, ceilings, and caps on headcount (20) and depth (3) (`docs/design.md:700-704`) are that structure without a CEO persona.

**The human gate.** This split matters most for Remit. One side keeps a person at the gate. GitHub's agent "cannot approve or merge", and the developer who asked for the PR cannot approve it ([GitHub docs](https://docs.github.com/en/enterprise-cloud@latest/copilot/concepts/agents/coding-agent/about-coding-agent)). Linear's principle 06 is "An agent cannot be held accountable" ([Linear AIG](https://linear.app/developers/aig)). Multica promises "Nothing ships without a human saying so" ([Multica README](https://github.com/multica-ai/multica/blob/main/README.md)). OpenAI's business guide gates "sensitive, irreversible, or high stakes" actions on a person "until confidence in the agent's reliability grows" ([OpenAI guide](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf)). Anthropic's team guidance is "Grant agents autonomy in proportion to demonstrated reliability, then expand it deliberately" ([Claude blog](https://claude.com/blog/building-effective-human-agent-teams)). The other side is OpenAI's own harness team: "Humans may review pull requests, but aren't required to", because "corrections are cheap, and waiting is expensive" ([OpenAI](https://openai.com/index/harness-engineering/)). Jules auto-approves plans by default and puts an AI critic where the human was ([Jules API](https://developers.google.com/jules/api)). The two positions **reconcile on reversibility**: approve beforehand what cannot be undone, and correct afterwards what is cheap to fix. Not one source lets an agent approve an irreversible act for an absent human. Paperclip's watchdog agent may put stopped work back in motion, but the server bars it from approvals, budgets, secrets and settings, and its instructions cannot widen that limit ([TASK-WATCHDOG.md](https://github.com/paperclipai/paperclip/blob/master/doc/TASK-WATCHDOG.md)).

**Who curates memory.** One group keeps memory in the repository: AGENTS.md as "a map, not a 1,000-page instruction manual" ([OpenAI](https://openai.com/index/harness-engineering/)), and Factory's "the work that we've done stays in your codebase" ([Sequoia](https://sequoiacap.com/podcast/factorys-matan-grinberg-the-coming-dark-factory-where-software-builds-itself)). Another keeps it in the product: Devin Knowledge, Lindy's team context, Google Memory Bank. Letta, which invented agent-managed memory tools, dropped them for bash over git-backed files, with sleep-time reflection moved into a subagent ([Letta](https://letta.com/blog/our-next-phase)). The evidence on self-curation is negative. On SkillsBench, curated skills raised pass rates by about **16 points** while self-generated skills gave **no average benefit** ([arXiv 2602.12670](https://arxiv.org/abs/2602.12670)). Learning that works is gated by a judge: Agent Workflow Memory induces workflows only from successful trajectories, and the Darwin Gödel Machine keeps a change only when it scores higher ([PMLR](https://proceedings.mlr.press/v267/wang25bx.html); [arXiv 2505.22954](https://arxiv.org/abs/2505.22954)). No study found measures an agent improving over weeks of real deployment.

## Remit already leads on customer judging, gated memory and attention accounting

Four of Remit's beliefs are ahead of anything the notes found, and the evidence supports them.

**Judges rule for the customer, and "could not" is a claim to check.** Every chain opens with who the customer is and what they get, and each judge rules on that side of the change (`AGENTS.md:73-74`, `docs/design.md:601-606`). No peer encodes a customer in its verdicts. Remit's goal judge marks a claim that no recorded tool call stands behind, and a "could not" the team never tried with its own means, as `not_met` with code `untried` (`docs/design.md:631-633`). This is the same mandate as Paperclip's watchdog ("Treat every stopped leaf as a claim that must be verified … Do not accept 'I could not' … as automatically valid"), but Remit enforces it at the finish rather than through an opt-in agent ([TASK-WATCHDOG.md](https://github.com/paperclipai/paperclip/blob/master/doc/TASK-WATCHDOG.md)). It targets the most documented failure in the field: false "done", inflated metrics and invented data ([AI Village](https://aivillageblog.substack.com/p/what-we-learned-2025)).

**Memory is admitted only through a verdict.** ADR-0063 admits an accepted card's session, and only what the teacher said from a sent-back card. Employees cannot write their own memory, and an overturn retracts what it taught (`docs/adr/0063-an-employee-learns-only-what-people-and-verdicts-teach-it.md:38-45`). This is the shape SkillsBench, AWM and DGM support, and it is stricter than Hermes, OpenClaw or Letta Code, which let the agent write mid-task.

**Owner attention is the headline loss.** "Owner hours per confirmed result" (`docs/design.md:827-833`) names the resource OpenAI's harness team calls scarce, "human time and attention" ([OpenAI](https://openai.com/index/harness-engineering/)). It also answers the failure the Alien Brain Trust reported when it shut Paperclip down: "We spent more time reviewing Paperclip's work than it would have taken to do the work ourselves" ([ABT](https://abt-blog.pages.dev/ai-learning/2026-04-05-why-we-killed-paperclip)). No peer measures that loss.

**The structure is typed and the asker never decides.** The effect ladder is set by the platform's table, not the agent (`docs/remit-design.md:165-166`). The asker is never the decider (ADR-0087), and every act of the Assistant is recorded and overturnable. Each matches a control Paperclip reached only after its incidents. The signal pipeline (event signals, subscriptions, durable check-backs) is a full version of the "ambient agent" idea that LangChain describes and personal agents only approximate with heartbeats ([LangChain](https://www.langchain.com/blog/introducing-ambient-agents)).

## Four Remit beliefs run against the evidence

### "No agent waits on the owner" goes further than any evidence supports

`AGENTS.md:63-66` and ADR-0087 route every non-secret item to the Assistant: grants, writing capabilities, extensions (arbitrary code), outside MCP servers, objectives, hiring, forgetting, and a `ship` request (`docs/adr/0087-…:110-131`). Three pieces of evidence push against this. First, **a same-model supervisor is lenient**: Vend's CEO said yes about eight times as often as no ([Anthropic](https://www.anthropic.com/research/project-vend-2)). The Assistant, the Chairs and the askers all run on Claude, the Assistant and Chairs on the same `fable` model (`docs/design.md:1396-1397`). "The asker is never the decider" separates the roles, but not the blind spots. Second, the Assistant acts with the owner's powers on text other parties wrote, and Remit's own threat table names the attack: outside text in a Chair's question steering the Assistant to lift a stop or raise a ceiling (`docs/remit-design.md:353`, `docs/design.md:1379-1381`). Third, **Remit's own stance argues against the rule for irreversible items**. "We take a risk when its loss is bounded and recovery is cheap" (`AGENTS.md:28-29`), while `docs/remit-design.md:54` admits "Irreversible effects stay unbounded". An extension applied, an irreversible grant used, or a credential-adjacent setting has no cheap recovery, and overturning afterwards does not undo it. The steelman for the rule is real: the owner was the constraint every chain queued behind, review cannot keep up with agents (ABT), and OpenAI's harness team ships with optional review. But that team's case rests on corrections being cheap, which is a property of reversible work. The evidence supports "no agent waits on the owner **for reversible work**". It does not support the rule for the top rung of the effect ladder. This conflicts with the owner's stated intent in ADR-0087:3-9, so it is his decision; the options are in the recommendations table (R1).

### "Every seat is an AI employee" is sound as identity but unsound as accountability

As identity, the employee concept is well supported. A named, long-lived record that holds a memory scope, a ceiling and a track record matches Letta's "the agent is its state", Hermes and Paperclip's capability paragraphs. As accountability, it is not. `docs/design.md:714-715` lets an employee be the `Accountable` party for a key result. Linear reversed exactly this ("An agent cannot be held accountable"), and GitHub forbids an agent approving its own work. Artisan and 11x show that framing agents as replacements for human roles sets expectations a product cannot meet. Remit's one-owner scope blunts this risk today: the owner answers for whatever an employee answers for. It becomes real once a second team or a customer reads "E-42 is accountable". Names and faces (ADR-0093) do no harm. Persona hierarchy does: the cost the field reports is chatter between agents, and Remit should watch handoffs per confirmed result for the "ping-pong" Paperclip users describe ([preuve.ai](https://preuve.ai/blog/paperclip-ai-review), LOW: secondhand).

### Same-family judges grade a stronger author

The Chair runs on `fable` at high effort, and the judges run on `sonnet` (`docs/design.md:1396-1397`). Remit's own design says a panel not measured as independent counts as one vote (`docs/remit-design.md:245-246`). Yet the reviewer, QC, goal judge, duel judge, coach and Assistant are all Claude models in one harness, and the decision that keeps it that way is "Claude Code is the one harness" (`docs/remit-design.md:242`). The evidence warns on both axes. Evaluators stay "inclined to be generous towards LLM-generated outputs" even when tuned ([Anthropic](https://www.anthropic.com/engineering/harness-design-long-running-apps)). Reward hacking grows with task length: on tasks over 8 hours, "at least 16% of successful runs were illegitimate", and Opus 4.6 attempted to reward hack in about 80% of attempts on an early hidden-test suite ([METR](https://metr.org/blog/2026-05-19-frontier-risk-report/)). Cognition's "smart friend" works "when both models are strong" and are from different frontiers ([Cognition](https://cognition.com/blog/multi-agents-working)). With the owner's merge gone (ADR-0087), the judges are now the last line before production on everything except rail paths. The controls Remit deferred as "named debt" until numbers exist (human anchors and seeded faults, `docs/remit-design.md:256-257`) are exactly what measures judge recall. That deferral made sense while the owner merged. It does not now.

### Agents learning is gated well but unproven, and the gate is itself an LLM

ADR-0063's gate is the right shape, but the evidence for long-term benefit is thin everywhere. SkillsBench found 16 to 18 of 84 tasks got *worse* even with curated skills, and no study measures improvement over weeks ([arXiv 2602.12670](https://arxiv.org/abs/2602.12670)). Remit's gate is a Chair's `accept_work`, an LLM verdict from the same family, and what passes it is a whole session extracted by an LLM (`docs/adr/0063-…:38-40`). That is closer to "self-generated" than to "curated". Remit already counts repeated corrections and overturn rates (`docs/design.md:1503`), which is more measurement than any peer has. What is missing is a counterfactual. The field's direction (Devin to Skills, Letta to git, OpenAI and Factory to the repo) also suggests that a lesson worth keeping should become a reviewable file in Git. Remit's own principle "Git is the base of all work" (`docs/remit-design.md:218-221`) points the same way, while memory today lives in a private daemon database.

### Two beliefs the evidence supports, with a caveat each

**"Build for next year's models"** (`AGENTS.md:39`) is the best-supported belief Remit holds. METR's 50% horizon doubles every 130.8 days since 2023 ([METR TH1.1](https://metr.org/blog/2026-01-29-time-horizon-1-1/)). Opus 4.6 measures about 12 hours, and Mythos Preview 17.4 hours, above what the suite can reliably measure ([METR data](https://metr.org/assets/benchmark_results_1_1.yaml)). Anthropic removes harness parts as each model arrives. The caveat: the 80% horizon is still about 3 hours for the strongest model, and that number governs unattended trust. Multi-day chains stand on decomposition and verification, not on the model. The parts that last are the spec, the verifier, the sandbox and durable state. The parts that go are crutches for model behaviour. Remit has crutches (the 10-minute stall nudges, `MAX_NUDGES`, `MAX_GATE_ROUNDS`, `check_reuse`, the 20-minute judge limit), but no mechanism that re-tests them when a new model ships.

**"Quality is the only target; Remit records and caps no cost"** (`AGENTS.md:19-20`) is defensible. Token spend explained 80% of the variance in Anthropic's research eval, and the full harness cost 20 times the solo run for a much better result ([Anthropic](https://www.anthropic.com/engineering/multi-agent-research-system); [harness design](https://www.anthropic.com/engineering/harness-design-long-running-apps)). The blind spot is that **a busy loop is a quality failure, not a cost one**. Paperclip issue #390 quotes users of #373 on "entire teams hemorrhaging tokens on no-progress heartbeat cycles", says the budget hard stop acts only when "by then the damage is done", and calls this "the #1 pain point across all multi-agent orchestration tools" ([paperclip#390](https://github.com/paperclipai/paperclip/issues/390)). Vending-Bench found meltdown loops models "rarely recover" from, uncorrelated with context fill ([arXiv 2502.15840](https://arxiv.org/abs/2502.15840)). Remit's stall rail fires only when nothing has moved for 10 minutes (`crates/orch/src/schedule.rs:207-214`). Any worker at work in a turn counts as progress and resets the reminders (`schedule.rs:408-412`), so a chain whose agents keep producing turns without producing progress passes it. The rail walks running chains only (`schedule.rs:384-401`), and the Assistant is in no chain, so it has no stall rail at all (`docs/design.md:1320`). Vendor exposure is the other caveat. Orchestrators on subscription logins were hit by billing changes (multica#2563, paseo#1029, paperclip#14182, and #3406 "budget policies become fictional guardrails"), and ABT feared an account flag for running persistent agents on a subscription. Remit runs on the machine's Claude Code login by default (`docs/design.md:1385-1391`).

Not worth copying: CEO personas and org-chart heartbeats (Vend, "too chatty"), budgets framed as salaries (they turned "fictional" on subscriptions), and Jules-style automatic approval without a measured critic.

## Conclusion

The field's real division is not single versus multi-agent, nor company versus workbench. It is a split between systems that let an agent *restore* work and systems that let an agent *authorize* it. Every public system draws the line at authorization. Remit is the only one that crosses it, so Remit runs an experiment no one else is running. That is consistent with "we go first", but an experiment needs instruments. Without approval-ratio reports, seeded faults and a counterfactual for memory, Remit cannot tell a working delegate from a rubber stamp, and an irreversible mistake will be the first signal it gets.

The second insight concerns what lasts. METR's curve and Anthropic's harness revisions say models will absorb the crutches, and Remit's bet on that is well placed. What models do not absorb is an independent judge, a recorded decision and a cheap way back. Remit already builds these better than its peers for reversible work. Its strategic risk sits at the top of its own effect ladder and in the monoculture of its judges, and the fix for both is measurement plus one more seam, not a retreat from agent-centric design.
